# 图片猎人 ImageHunter

**把一个网页上的图片全部找出来 —— 按需筛选、批量下载，而且保证拿到的是原图。**

适用于 **Chrome / Edge** 的浏览器扩展（Manifest V3）。
**零依赖、零构建** —— 克隆下来用「加载已解压的扩展程序」指到本目录就能跑，不用 `npm install`，也没有构建步骤。

## 它解决什么问题

浏览器的「图片另存为」有三个长期痛点：

1. **存下来的是缩略图。** 很多站点在列表页给的是 `xxx-300x200.jpg`，右键存下来就是这张小的。
2. **一张一张存太慢。** 一页几十张图，右键 → 另存为 → 选目录 → 保存，重复几十次。
3. **存完就找不到了。** 文件名是 `image (1).jpg`、`image (2).jpg`…… 全堆在下载目录里。

图片猎人把这三件事一次解决：**嗅探全页 → 筛选 → 勾选 → 批量下载**，
并且每一步都保证「拿到的是能拿到的最大的那张原图」。

## 核心特性

### 1. 悬停即存原图

鼠标移到任意图片上，右上角浮现一小组圆形按钮（左：放大镜预览，右：下载箭头）。
点下载直接保存原图，不用再走右键菜单；图标随滚动实时跟随，鼠标移开自动消失。

- 下载键**四态反馈**：待下载 → 保存中（转圈）→ 成功（绿勾）→ 失败（红叹号，可再点重试）
- 下载键**永远停在图片右上角**，预览键往左长出去 —— 老用户的肌肉记忆不会被挪位置
- `Alt + 点击图片` 可免悬停直接保存；右键菜单也有「保存此图片（原图）」

### 2. 全页嗅探 → 图库

点扩展图标，在**新标签页**打开完整图库（不是小弹窗）。自动锁定你刚才在看的那个标签页作为扫描目标，
顶部下拉框可随时切换目标、切换即重新嗅探。

- **11 类来源**：`<img>`、`srcset`、`<picture>`、懒加载属性（`data-src` 等）、CSS 背景图、伪元素背景图、
  `video poster`、内联 SVG、链接指向的图片、`preload`、`og:image` —— 且**含所有 iframe**
- **多维筛选**：分辨率预设（≥800 / ≥1200 / ≥1920 / ≥2560）、最小尺寸连续滑条（0–4096px，**默认 256**）、
  宽高比、格式、来源、关键词搜索
- **排序**：分辨率 / 体积 / 页面顺序 / 站点
- **批量操作**：拖拽框选、全选、清空、批量保存，顶栏实时显示「已选 N 张 · 合计 X MB」

### 3. 保证是原图 —— 三层机制

这是本项目最核心的技术点：

1. **`srcset` 取最大** —— 解析 `<img srcset>` 与 `<picture><source srcset>` 的 `w` / `x` 描述符，取最大的那个
2. **缩略图地址还原** —— 内置规则覆盖：WordPress 尺寸后缀（`image-1024x768.jpg` → `image.jpg`）、
   路径尺寸段（`/w_400/`、`/300x200/`、`/thumbs/`）、查询参数（`?w=400&h=300&q=80`）、
   Cloudinary、七牛、阿里云 OSS、百度云加速、又拍云、淘宝 CDN……
3. **实测择优（关键保护）** —— 所有还原出的候选地址都会**真实加载验证**，
   **只有加载成功且像素面积确实更大**才会采用，否则回退原地址。从机制上杜绝「把好链接改坏」

> 原图还原整轮有 **8 秒时间预算**，超预算时靠后的图会保持页面上的缩略图地址（底栏如实提示）。
> 每张这样的卡片右下角有「还原」按钮，点它单独重试这一张。

### 4. 大图预览查看器

点悬停按钮里的放大镜，**就地**打开全屏灯箱 —— 不会把你甩到别的标签页。
`←` `→` 翻页、`Esc` 关闭，灯箱顶栏还有「在图库中打开」。

### 5. 键盘可用 + 读屏器可用

图库网格是一个标准的多选列表（`role="listbox"` + `role="option"`），
键盘能完整走完「挑图 → 保存」这条路：

| 按键 | 作用 |
|---|---|
| `Tab` | 进入 / 离开网格（**整个网格只占一个 Tab 停靠点**） |
| `←` `→` `↑` `↓` | 在卡片之间移动焦点 |
| `Home` / `End` | 跳到第一张 / 最后一张 |
| `PageUp` / `PageDown` | 按可视高度翻页 |
| `Enter` / `空格` | 勾选 / 取消当前这张 |
| `P` | 打开大图预览 |
| `R` | 对没还原成功的图单独重试 |

细节上做了这些：**roving tabindex**（2,000 张卡片不会变成 2,000 个 Tab 停靠点）、
聚焦时悬停按钮必须显形（修 WCAG 2.4.7）、状态变化走 `aria-live` 播报且带 180ms 防抖。

### 6. 其余值得一提的

| 功能 | 说明 |
|---|---|
| **深度嗅探** | 滚动整页、边滚边采，把「要滚到底才加载」的无限滚动站点也拿全 |
| **多标签页合并嗅探** | 可选开关，默认关。勾几个已打开的页面合并成一份列表，按地址跨页去重、每张标注来源页 |
| **体积探测** | 对每张图发 `HEAD`（不支持时降级 `Range: bytes=0-0`），只读 `Content-Length`，不下载本体就能按体积排序 |
| **扫描结果缓存** | 同标签页同地址，5 分钟内重开图库直接复用，底栏如实标出「复用 N 分钟前的嗅探结果」 |
| **导出清单** | 左键导出 JSON、右键导出 CSV（文件名 / 尺寸 / 体积 / 格式 / 来源 / 是否已还原 / 地址） |
| **按站点或日期分目录** | 模板 `{host}` / `{date}` / `{index}`，批量下载几百张不会全堆在下载目录里 |
| **站点排除列表** | 网银、在线编辑器这类不想被打扰的站点，那里就不显示悬停按钮、不响应快捷键 |
| **自定义还原规则** | 设置页写正则，带**规则调试器**（粘贴地址即可看到会生成哪些候选、能否加载、是否会被采用） |
| **三个全局快捷键** | `Alt+Shift+S` 页内面板 / `Alt+Shift+G` 打开图库 / `Alt+Shift+D` 保存当前悬停的那张 |
| **自助排障诊断包** | 设置页一键导出 JSON。**只含聚合数字与主机名**，不含图片地址 / 页面地址 / 文件路径 |

## 安装

### 方式一：开发者模式加载（推荐）

1. 克隆或下载本仓库
2. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
3. 打开右上角的**开发者模式**
4. 点**加载已解压的扩展程序**，选择本目录
5. 工具栏出现扩展图标（若未显示，点拼图图标把「图片猎人」固定到工具栏）

> 修改代码后，回扩展管理页点该卡片上的**刷新**按钮即可生效。

### 方式二：打包成 zip

```bash
node tools/package.js          # → dist/image-hunter-v<版本>.zip
node tools/package.js --list   # 只列出会打进包的文件
```

零依赖（压缩用 Node 内置的 zlib）。打包白名单是**从 `manifest.json` 递归算出来的**，不是手写清单 ——
手写清单迟早会烂：加了个文件忘了写进去，打出来就是残包，而且要**到用户装上才发现**。
时间戳固定，所以同样的源码永远打出**字节相同**的 zip（可复现构建）。

### 权限说明

| 权限 | 用途 |
|---|---|
| `downloads` | 保存图片到浏览器默认下载目录 |
| `storage` | 保存设置、下载历史、去重指纹 |
| `contextMenus` | 图片 / 页面右键菜单 |
| `scripting` | 在已打开的页面补注入内容脚本 |
| `<all_urls>` | 嗅探任意网站的图片（含 iframe）—— 核心能力的必然要求 |

扩展**不收集、不上传任何数据**，所有设置 / 历史 / 指纹都只存在本机。

## 快速上手

1. 打开任意有图片的网页
2. **存一张** —— 鼠标移到图片上，点右上角的下载箭头
3. **存一批** —— 点工具栏图标打开图库 → 拖滑条 / 搜关键词缩小范围 → 勾选 → 点「保存」
4. **想存原图** —— 默认就是。卡片右下角有「还原」按钮的，是这一轮没来得及还原的，点它单独重试

> 图库打开时尺寸滑条**默认就在 256**，所以短边小于 256px 的小图标不会出现 ——
> 这不是嗅探漏了。想看到全部，把滑条拖到 `0`。

├── background.js          # Service Worker：下载队列、消息路由、历史/指纹、体积探测
├── shared/                # 消息常量、URL 工具、存储封装、诊断包（纯函数）

## 开发

```bash
npm ci                 # 首次：装开发期依赖（jsdom + playwright-core）
npm test               # Node 套件（15 个）
npm run test:browser   # 真实浏览器套件（25 个，需要本机 Edge / Chrome）
npm run test:all       # 两个入口都跑
npm run package        # 打包
npm run audit:settings # 巡检设置项：列出每条设置的读取点 / UI 挂点，找死设置
```

- **扩展本体零依赖零构建。** `package.json` 里声明的全是**开发期**依赖，不进扩展包
- 浏览器套件第一次跑要先装一份**完整** Chromium（headless shell 不支持 `--load-extension`）：
  `npx playwright-core install --with-deps --no-shell chromium`
- 当前实测：Node **15 套件 / 774 项**、真浏览器 **25 套件 / 647 项**，合计 **1,421 项**，全绿
- CI 在 [`.github/workflows/ci.yml`](.github/workflows/ci.yml)：`push` / `pull_request` 都跑两个入口，
  两个 job 都**不允许 `continue-on-error`** —— 一个会失败但被忽略的检查，比没有检查更糟

> **测试上最值得一看的不是数量，是 [`tests/README.md`](tests/README.md) 里的 20 个坑。**
> 断言前提写错、静态守卫扫到自己的注释、手写清单漏一项不报错、把中间结果当最终结果去断言……
> 每个坑都配了判据与做法。这份文档比测试本身更能说明这个项目对「结论可信」的要求。

## 技术要点

- **零构建、零依赖** —— 原生 ES2020，不需要 npm / webpack / 打包器，直接加载即可运行
- **Shadow DOM 隔离** —— 页内 UI 全部封装在 Shadow DOM 中，站点 CSS 污染不到它，它也污染不到站点
- **多 iframe 汇总** —— 内容脚本注入到所有 frame，各自独立扫描后由后台合并去重
- **MV3 休眠应对** —— 下载托管给浏览器 `downloads` API，队列持久化到 `storage.session`，
  Service Worker 被回收后能自动恢复未完成的下载
- **并发限流** —— 尺寸探测与下载都有并发闸门，图片再多也不会拖垮页面
- **可复现打包** —— 时间戳固定，同样源码永远打出字节相同的 zip
- **行尾统一 LF** —— 由 `.gitattributes` 钉住；否则「两次打包字节相同」会在别的机器上莫名变红

## 常见问题

**Q：图库打开后有些小图不显示，是嗅探漏了吗？**
不是。筛选条「尺寸」那一格的下排滑条**默认就是 256**，短边小于 256px 的会被过滤掉。
滑条右侧和「筛选」按钮上的角标会实时显示条件数。想看全部，把滑条拖到 **0**。

**Q：界面有英文版吗？**
没有，界面文案目前 **100% 是中文硬编码**。`_locales/` 只有 8 个键
（扩展名称 / 描述 / 命令标题 / 右键菜单文案），是给 manifest 用的，不覆盖任何界面文字。
想要英文界面欢迎提 issue。

**Q：某些图片保存失败？**
少数站点有严格的防盗链校验。扩展会自动尝试降级方案（改用扩展页拉取），若仍失败，
可在图片上右键选择「在新标签页打开原图」后手动保存。

**Q：为什么某张图没显示悬停下载图标？**
默认小于 64px 的图片不显示图标（避免小图标、分隔条干扰）。可在设置页调低「最小显示尺寸」。

**Q：点了下载提示「已保存」，但下载目录里没有？**
先看提示的具体文案：「已下载过，本次已跳过」= 指纹命中了；
「已保存原图 …（实际为 xxx.avif）」= Chrome 按真实 MIME 纠正了扩展名，按提示里的文件名找。

**Q：「最小显示尺寸」和「大图预览最小尺寸」有什么区别？**
一个管**悬停图标**（判图片的**显示大小**，决定能不能点），
一个管**灯箱翻页**（判图片的**真实像素尺寸**，决定翻不翻得到），互不影响。
