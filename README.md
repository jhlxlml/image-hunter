# 图片猎人 ImageHunter

一个适用于 **Chrome / Edge** 的浏览器扩展（Manifest V3）。

**核心承诺：存下来的永远是原始分辨率的大图，不是缩略图。**

---

## 功能一览

### 1. 单张图片快速保存 —— 图片右上角一键下载

鼠标悬停在任意图片上，图片**右上角浮现一小组圆形按钮**（左：放大镜预览，右：下载箭头），
点下载**直接保存原图**，无需再走浏览器右键「另存为」；点放大镜**就地打开大图预览**。

- 图标随滚动实时跟随，鼠标移开自动消失，不干扰正常浏览
- 下载键四态反馈：待下载 → 保存中（转圈）→ 成功（绿色对勾）→ 失败（红色感叹号，可再点重试）
- **下载键永远停在图片右上角**，预览键往左长出去 —— 老用户的肌肉记忆不会被挪位置
- 自动过滤掉小图标、分隔条、追踪像素（默认小于 64px 的图片不显示图标）
- `Alt + 点击图片` 可免悬停直接保存
- 右键菜单也提供「保存此图片（原图）」

### 2. 全页批量嗅探 + 按需筛选 + 一键批量保存

**点击扩展图标 → 在新标签页里打开完整图库**（不再是小弹窗），空间更大、看得更清楚：

- 打开时自动锁定「你刚才正在看的那个标签页」作为扫描目标
- 顶部「扫描目标」下拉框可在多个已打开的标签页之间随时切换，切换即重新嗅探
- **多标签页合并嗅探**（可选，默认关）：在设置里打开后，顶部的「扫描目标」
  从单选下拉变成**多选勾选列表**，可以一次勾上好几个已打开的页面，
  把它们上面的图片**合并成一份列表**再一起挑（见下）
- 重复点击图标只会切回已打开的图库页，不会越开越多

#### 多标签页合并嗅探（默认关，在设置里开）

浏览一个商品的多页详情、一次调研的多个来源时，常常想「把这几页的图放一起挑」。
打开 **设置 → 嗅探范围 → 多标签页合并嗅探** 后：

- 顶部的「扫描目标」变成勾选列表，勾几个页面就合并几个（还有「全选 / 清空」）
- **按图片地址去重**：同一张图出现在多个页面时只留一张
- 每张卡片左上角标出**来自哪个页面**（`来源页` 角标），一眼分得清
- 「站点」排序在合并时先按来源页分组，页内再按图片域名
- 搜索会连**来源页地址**一起匹配 —— 输入 `example.com` 就只剩那一页的图
- 导出的清单多一列 `来源页`，合并结果不会因为导出就分不清出处
- 勾选列表里原来那一页如果**已经被关掉**，会自动退回到后台推荐的那一页
  （不会留下一个指向死标签页的勾选）；一个都没勾时空态会直说
  「还没有勾选要嗅探的页面」，而不是含糊的「本页没有发现图片」

> 为什么默认关：**只扫当前这一页**是绝大多数时候想要的行为。
> 合并是一次「有意的额外动作」，不该默认替用户打开 ——
> 打开后每次都要多扫好几个页面，那是实打实的开销。
>
> 页内面板（`?mode=panel`）**不提供**合并：面板是贴着当前这一页的窄条，
> 装不下多选面板，语义上也不该去扫别的标签页。

图库自动嗅探目标页面（含所有 iframe）的图片：

- **11 类来源**：`<img>`、`srcset`、`<picture>`、懒加载属性（`data-src` 等）、CSS 背景图、伪元素背景图、`video poster`、内联 SVG、链接指向的图片、`preload`、`og:image`
- **多维筛选**：分辨率快捷预设（≥800 / ≥1200 / ≥1920 / ≥2560）、**最小尺寸连续滑条**（0–4096px，**默认 256**）、宽高比（横/竖/方/超宽/超长）、格式、来源、关键词搜索
- **排序**：分辨率、体积、页面顺序、站点
- **快速勾选**：点卡片即勾选，`Shift + 点击` 连选，`Ctrl/Cmd + A` 全选，支持「全选」「反选」「清空」
- **鼠标拖拽框选**：在网格里按住鼠标左键拖出一个矩形，**框内未勾选的会被勾上、已勾选的会被取消**（切换语义）。
  于是多次框选不同区域天然是**累加**，框回已选区域就是**反选取消**；
  `Ctrl` 拖 = 只加不减、`Alt` 拖 = 只减不加、`Esc` = 放弃本次框选
- **一键批量保存**：并发下载、失败自动重试、实时进度条与成功/失败/跳过统计
- **每张仅留最大**：自动把同一张图的不同尺寸版本归并，只保留最大的那个

> 图库打开后**默认不勾选任何图片**，一切从你的选择开始。

#### 勾选永远只存在于「当前筛选结果」内

筛选不只是「看得见哪些」，它就是**缩小工作集**：

- 切换筛选条件时，**不在新结果里的图片会被自动取消勾选**，并弹一句「已取消 N 张不在当前筛选内的勾选」
- 所以底栏的「已选 N」永远等于你**眼前能看到并勾上的数量**，点「保存选中」绝不会悄悄多出几张已经被筛掉、看不见的图
- 由此「全选」就等于「勾上当前筛选出的全部」（按钮上直接标着数量），「反选」也只在筛选结果内翻转
- 反过来，**把筛选放宽（清掉条件）不会让之前被取消的勾选复活**——取消就是取消了

> 如果你想要「跨多轮筛选慢慢攒一批再一起保存」，这个语义就不适合。
> 替代做法：先别筛，直接拖拽框选把一批攒起来，最后再筛一遍确认。

#### 尺寸：档位与连续滑条（互斥、档位优先）

最小尺寸有**两个控件**，同一个维度从粗到细，**分处两行**：

- **筛选条「尺寸」格里的 chips**：`全部` `≥ 800px` `≥ 1200px` `≥ 1920px` `≥ 2560px` —— 一行点选，快
- **工具行最右侧的连续滑条**：`0 – 4096px` 可拖，**默认 256**，右侧实时显示当前阈值（如 `≥ 256px`）

> 滑条**不在筛选条里**，而是放在搜索 / 筛选 / 排序 / 全选那一行的**最右端空白处** ——
> 那里本来就空着，滑条塞进去不占额外行高；同时筛选条里「尺寸」这一格只剩 chips，
> 和「比例 / 格式 / 来源 / 其他」一样高，整条筛选栏不再有一格特别高。

两者是**互斥**的，规则只有一条：**chips 选了非「全部」，就听 chips；否则听滑条。**

- 依据 chips 选中档位时，滑条整枚控件**变淡**（半透明，不是禁用 —— 仍可拖），
  悬停会提示「当前由上方档位（≥ 800px）决定；拖动这里会切回滑条」。
  这样不会出现「两个条件叠加了」的误解
- **拖滑条 = 明确表达「我要用连续这一把」**，于是会把档位 chips 自动复位成「全部」（避免「拖了没反应」）
- `0` = 不过滤；阈值写 **0** 就是关掉这个维度（滑条右端显示「不过滤」）

> 两个控件的**判据不同，是刻意的**：
> chips 判**宽度**（`≥ 800px` = 宽 ≥ 800），滑条判**较短边**（`min(宽, 高) ≥ 阈值`）。
> 滑条用短边是因为它替代的是「这张图够不够大」这个直觉 —— 一张 `1200×8` 的分隔条
> 宽度足够但根本没法看，短边判据能把它挡掉。滑条右端最大值 **4096** 也超出了上排最高档 2560。

> **滑条的默认值是 256，也就是说图库打开时**就已经**在按短边 256 过滤了。**
> 想看到全部（含小图、图标、间距图），把滑条拖到 **0**。
> 这个值是**视图状态**，存在本地、跟排序和搜索词同类，**不进设置页、也不会被导出/导入**。

> 阈值判的是图片的**真实像素**（探测得到的宽高）。尺寸未知的图**一律放行** ——
> 宁可多一张，也不静默藏图。

#### 尺寸过滤把结果清空时：空态会说清原因，并给一键出口

默认 256px 是个「好图库」的门槛，但列表页、缩略图站点的图**大量在 200px 上下**，
所以打开图库**第一眼就撞上空列表**是很正常的事。为了不让它看起来像坏了，空态分三种：

| 空的原因 | 界面怎么说 |
| --- | --- |
| 这一页本来就没有图片 | 「没有嗅探到图片」+ 提示滚动页面或深度嗅探 |
| 有图，但被**尺寸过滤**挡住了 | 「48 张图片都被「最小尺寸 ≥ 256px」挡住了 / 这一页的图片短边都小于 256px」+ **〔显示全部 48 张〕** 按钮 |
| 有图，但被**别的条件**（比例/格式/来源/搜索）清空了 | 「没有符合当前筛选条件的图片」+ 提示放宽条件 |

第二种的 **〔显示全部 N 张〕** 就是专用出口：点一下把**档位与滑条两条尺寸条件一起清掉**
（滑条归 0），当场看到全部；而且这个「清掉」会**落盘**，下次打开图库或页内面板
不会又把旧阈值捡回来。

> 判「是不是只有尺寸在挡」用的是**真筛一遍**（把尺寸条件去掉，看剩下的图是不是非空），
> 而不是猜 —— 保证只在尺寸确实唯一挡道时才给出口，不会给出一个按了也没用的按钮。

#### 无限滚动 / 越滚越多的页面：深度嗅探

普通嗅探只看**此刻已经存在**的图片。微博、Pinterest、电商瀑布流这类站点要滚到底
才加载下一批，所以直接嗅探只能拿到首屏那几十张。

点顶栏的 **深度嗅探**（向下箭头带横线的图标）即可解决：

- 扩展会**自动把页面滚到底**，边滚边采集，滚不动了就停
- 滚动期间加载动画上会实时显示「已采集 N 张 · 第 k 轮 · 本轮新增 M 张」
- 结束后**把页面滚回你原来的位置** —— 这是你的页面，没理由被滚乱
- 停止条件：连续 3 轮没有新图 / 到达文档底部 / 滚满 20 屏或超过 25 秒

> 只有真的滚到了上限才提示「深度嗅探已达滚动上限，页面里可能还有未采集到的图片」；
> 自然滚到底不会有任何多余提示。

#### 所有图片一次性全部显示

网格里**没有「显示更多」按钮**——本页嗅探到的图片会全部渲染出来，滚到底就是最后一张。

- 首屏先出 120 张（几乎立刻可见），剩下的用 `requestAnimationFrame` 在每一帧的空闲里**自动补全**，
  你不需要做任何操作，滚动条很快就是全长的
- 分片插入而不是一次性塞进 DOM，是为了几千张图时不把主线程卡住；
  实测 1200 张图约 350ms 全部渲染完，框选拖拽每帧约 3.7ms
- 图片本身仍用 `loading="lazy"`，浏览器只会加载真正滚进视口的那部分，不会一开页面就下几百兆

#### 界面：一屏内把「查 / 筛 / 选」都摆出来

为了既省空间又不把操作藏起来，顶部只保留两行结构：

| 位置 | 内容 |
|---|---|
| 顶栏 | 品牌 + **紧凑的扫描目标下拉** + `探测体积` `导出清单` `重新嗅探` `深度嗅探` `页内面板` `设置` 图标按钮 |
| 工具行 | `🔍`（点开才展开成输入框）· `筛选`（收起/展开筛选条，带生效条件角标）· `排序`下拉 · **`全选` `反选` `清空` 平铺一组** |
| 筛选条 | 尺寸（**档位 chips + 连续滑条**）/ 比例 / 格式 / 来源 / 其他 —— 五组条件**直接平铺**，宽屏自动并成一行 |
| 底栏 | `共 N 张 · 符合 N · 已选 N · 合计体积` + `保存选中 (N)` |

几条明确的设计取舍：

- **搜索框平时只是一个图标**。点一下在原位展开成输入框（不推动其它控件），回车或点别处收起；有搜索词时图标常亮，一眼看出「结果被搜过」
- **筛选条件不折叠进浮层、也不进二级菜单**。五组 chips 直接平铺可见，用「内联标签云」排布——宽屏并成一行，窄屏自然换行
- **「尺寸」把粗筛和精筛放在同一格**：上排档位 chips 负责快选，下排连续滑条负责精调，一眼看出二者是同一维度。档位生效时滑条变淡（而非禁用），不会产生「条件叠加」的误解
- **批量选择三个动作平铺**成一组分段控件：「全选」上直接标着当前筛选出多少张，不用先点开菜单
- **统计压成一行小字**放进底栏，和「保存选中」待在一起
- 独立页模式整块控制区**吸顶**；页内面板模式（窄）默认把筛选条收起，点「筛选」即可展开
- 控件全部有 hover 抬升、渐变选中态、阴影层次；「探测体积」探测期间图标转圈表示在忙

竖向占用：**原始三段式约 204px → 现在约 137px**（筛选条展开、五组条件全可见）。


### 3. 保证是原图 —— 三层机制

这是本扩展最核心的技术点：

1. **srcset 取最大**：解析 `<img srcset>` 与 `<picture><source srcset>` 的 `w` / `x` 描述符，取最大的那个
2. **缩略图地址还原**：内置规则覆盖常见场景
   - WordPress 尺寸后缀 `image-1024x768.jpg` → `image.jpg`
   - 路径尺寸段 `/w_400/`、`/300x200/`、`/thumbs/`
   - 查询参数 `?w=400&h=300&q=80`
   - Cloudinary `/upload/w_400,h_300,c_fill/`
   - 七牛 `?imageView2/2/w/300`、阿里云 OSS `?x-oss-process=image/resize,w_300`
   - 百度云加速 `?x-bce-process=image/format,f_avif`（IT之家等站点的图床）
   - 又拍云 `pic.jpg!small`、淘宝 CDN `abc.jpg_300x300q75.jpg`
3. **实测择优（关键保护）**：所有还原出的候选地址都会**真实加载验证**，**只有加载成功且像素面积确实更大**才会采用，否则回退原地址 —— 从机制上杜绝「把好链接改坏」

   > 例外：像素尺寸**完全相同**、但去掉了图片处理参数的干净地址也会被采纳。
   > 这类地址是**未经转码压缩的真原图**（例如同一张图，转码版 AVIF 只有 52KB，
   > 原图 JPEG 有 746KB），靠面积比较永远分不出高下，必须单独识别。

#### 没还原成功的图，可以单独重试

原图还原要给每张候选发真实加载请求，所以整轮有 **8 秒时间预算**，按文档顺序推进 ——
超预算时牺牲的一定是靠后的图片：它们会保持页面上的缩略图地址（底栏会如实提示
「原图还原超时，靠后的部分图片仍是页面上的版本」）。

这些图以前只能靠「重新嗅探」补救，而重跑大概率还是超时。现在**每张这样的卡片右下角
都有一个「还原」按钮**，点它就对这一张单独重跑一次：

- 只给**确实存在原图候选**的图显示按钮（地址里没有任何尺寸 / 处理参数的图，本来就是原图，
  点了也是白等一次探测）—— 图库用的是和嗅探**完全同一套规则**
- 成功 → 卡片**原地**换成原图地址、尺寸更新、角标变成「原图」，按钮消失
  - 勾选状态跟着搬过去。还原会改 URL，而勾选是按 URL 的哈希存的 ——
    如果整格重建，你刚勾的图会全掉
- 确认没有更大的原图 → 如实提示「这张图已经是能拿到的最大的版本了」，并收掉按钮
- 失败（网络抖动 / 页面正在刷新）→ 保留按钮，再点一次即可

重试会**忽略上一次的探测缓存**：探测失败的结果同样会被缓存（避免反复重试同一个坏地址），
不清掉的话重试会直接命中缓存里的「失败」，按钮点了等于没点。

### 3.1 提示与实际结果严格一致

悬停下载的「已保存」气泡**只在文件真正落盘后才出现**，并且区分三种结果：

| 情况 | 提示 |
|---|---|
| 保存成功 | `已保存原图 1440×2132` |
| 命中「跳过已下载」 | `已下载过，本次已跳过`（不会伪装成已保存） |
| 失败 | 显示具体错误原因，图标变红 |
| 扩展名被浏览器纠正 | `已保存原图 …（实际为 xxx.avif）` |

最后一条是因为 Chrome 会按响应的真实 MIME 纠正扩展名 —— 如果 CDN 把 `.jpg` 转码成 AVIF，
落盘文件名就会变成 `.avif`。扩展会把**实际文件名**如实告诉用户，免得按 `.jpg` 去下载目录里翻不到。

### 4. 大图预览查看器

点卡片上的放大镜，或**直接悬停在网页图片上点放大镜**，打开全屏灯箱：

- **就在当前页面打开，不会把你甩到别的标签页**。图库页里点预览，灯箱就开在图库页里
- 滚轮缩放（20% ~ 800%）、拖拽平移、双击 1x/2x 切换
- `← / →` 切换、`Esc` 关闭、`S` 保存、`+ / -` 缩放、`0` 复位
- 底部缩略图条，显示真实分辨率与体积
- 一键保存原图 / 复制直链 / 复制图片到剪贴板 / 新标签页打开
- **网页里悬停预览也能左右翻**：点放大镜后，灯箱里是**本页全部图片**（按页面顺序），
  直接 `← / →` 或点缩略图条就能一张张看下去，不用退出去再点开
- **在图库中打开**：从网页里悬停预览时，灯箱顶栏多一个九宫格图标 ——
  点它直接跳到图库并**定位到当前这一张**（滚到可见 + 闪一圈 + 一句说明），
  接着用图库的筛选、框选、批量下载
- **按最小尺寸过滤**：设置页「交互」里的「大图预览最小尺寸」（默认 64px，可设 0 关闭）
  决定灯箱里能翻到哪几张。判据是**较短边** —— `1200×8` 那种分隔条会被挡掉，
  小图标也不会混进 `← / →` 里占位置。被挡掉的张数会写在底部计数旁边
  （如「6 / 12 · 已按 64px 过滤 19 张」），不会让人误以为是嗅探漏了图

> **这个门槛只管灯箱。** 图库卡片列表、批量下载、悬停下载图标一律不受影响 ——
> 想在图库里看到（并批量下载）小图标，把门槛调成 0 即可；
> 也可以就让它开着，图库里照样有，只是翻页时干净些。

> 尺寸判的是图片的**真实像素**（探测得到的宽高），不是页面上显示的大小；
> 探测超时、尺寸还未知的图**一律放行** —— 宁可多一张，也不静默藏图。

> 悬停预览要拿到整份列表，就得先把本页扫一遍（含原图还原，还原要给每张候选发一次
> 真实加载请求），所以点下去会**先转一小会儿圈**再说「正在整理本页图片…」。
> 这是刻意的取舍：宁可等一下直接看原图，也不要先把页面上的缩略图地址铺出来、
> 翻到一半再被换成另一批 URL。同一次会话里第二次点预览会命中扫描缓存，基本是瞬时的。
>
> 这个九宫格按钮只在**网页里的预览**中出现。图库页自己的灯箱不显示它（用户本来就在图库），
> 面板模式下也不显示（面板就在这个页面上，跳过去只会把焦点抢走）。

> 唯一例外是**页内面板**：图库本身是嵌在网页右侧的一条窄 iframe，灯箱开在里面只会被挤成一条，
> 所以面板模式下预览仍然交给网页来开 —— 那才是真正的全屏。

### 5. 下载进度与历史记录

- 实时进度条、成功 / 失败 / 跳过计数
- 保留最近 500 条下载记录（时间、文件名、尺寸、体积、状态、来源页），可在设置页查看
- 累计保存统计

### 6. 去重与跳过已下载

- 按「图片地址 + 尺寸」计算 SHA-256 指纹，已下载过的图片自动跳过
- 图库中会显示「已下载」角标，可一键隐藏
- 可在设置页清除指纹

### 7. 其他实用功能

- **三个快捷键**（可在 `chrome://extensions/shortcuts` 改）：
  - `Alt + Shift + S` —— 打开 / 关闭页内图库面板
  - `Alt + Shift + G` —— 在新标签页打开图库
  - `Alt + Shift + D` —— 保存**鼠标当前悬停的那张图**；灯箱开着时保存正在看的那一张
- **扫描结果缓存**：同一标签页、同一个地址，5 分钟内重新打开图库直接复用上次的结果，
  省掉「重新注入 + 重新还原原图」那几秒。命中时底栏会如实标出
  「复用 N 分钟前的嗅探结果」，点一下就是重新嗅探 —— 不会让你误以为是刚扫的
- **页内图库面板**：`Alt + Shift + S` 或点图库右上角，在当前页右侧滑出完整图库，边看页面边勾选
- **导出清单**：顶栏「导出」图标，左键导出 JSON，右键导出 CSV（含文件名、尺寸、体积、格式、来源、是否已还原原图、地址）
- **体积探测**：卡片上的「体积」平时只知道**你已经下载过**的那些（来自下载历史）。
  点一次顶栏的仪表图标，扩展会对每张图发一个 `HEAD` 请求（不被支持时降级为 `Range: bytes=0-0`），
  只读响应头里的 `Content-Length`，**不下载图片本体**就能拿到真实文件大小。用途：
  - 按「体积 大→小」排序，快速找出信息量最大的那几张（同尺寸下体积大的通常是更高质量版本）
  - 保存前先看底栏的「合计」，避免一次拉下几百 MB
  - 结合分辨率筛掉「尺寸大但体积很小」的伪高清图
- **自定义还原规则**：在设置页写正则，并带**规则调试器**（粘贴地址即可看到会生成哪些候选、能否加载、是否会被采用）
- **保存到子目录**：设置页填一个模板，按站点或日期自动分目录（`{host}` / `{date}` / `{index}`），
  批量下载几百张时不会全堆在下载目录里
- **站点排除列表**：把网银、在线编辑器这类不想被打扰的站点写进去，那里就不显示悬停按钮、不响应 Alt+点击、不开页内面板
- **浅色 / 深色 / 跟随系统** 主题
- **防盗链降级**：直链下载失败时自动改用扩展页拉取图片再保存，绕过部分站点的 403 限制

### 8. 键盘操作与读屏器

图库的网格是一个标准的多选列表（`role="listbox"` + `role="option"`），键盘可以完整地完成
「挑图 → 保存」这一整条路，不需要鼠标：

| 按键 | 作用 |
|---|---|
| `Tab` | 进入 / 离开网格（**整个网格只占一个 Tab 停靠点**） |
| `←` `→` `↑` `↓` | 在卡片之间移动焦点 |
| `Home` / `End` | 跳到第一张 / 最后一张 |
| `PageUp` / `PageDown` | 按可视高度翻页 |
| `Enter` / `空格` | 勾选 / 取消当前这张 |
| `P` | 打开大图预览（等价于点卡片右上角的放大镜） |
| `R` | 对这张没还原成功的图单独重试（等价于点右下角的「还原」） |

几个不做会很难受的细节：

- **roving tabindex**。网格里可能有 2,000 张卡片，如果每张都 `tabindex="0"`，
  键盘用户要按两千次 `Tab` 才能从第一张走到最后一张 —— 比不支持键盘还难受。
  所以只有「当前那一张」是 `0`，其余全是 `-1`，方向键负责挪这个停靠点。
- **悬停才出现的按钮，聚焦时也必须出现**。`.zoom` / `.restore` 原本是 `opacity: 0`、
  悬停才显形 —— 于是 `Tab` 能聚焦到一个**看不见的按钮**上（WCAG 2.4.7 违规）。
  现在 `.card:focus` 与 `.card:hover` 产生同样的可见结果。
- **卡片内的辅助按钮不占 Tab 顺序**（`tabIndex = -1`），键盘等价物分别是 `P` 和 `R`；
  勾选圈对整个无障碍树隐藏（`aria-hidden`）—— 它和卡片的 `aria-selected` 说的是同一件事，
  都念一遍只会让人以为有两个开关。
- **状态变化通过 `#srStatus` 播报**（`role="status"` + `aria-live="polite"`），
  且带 180ms 防抖：只念「已勾选 5 张」这种整句，不会把框选过程中的每个中间计数都念一遍。
  保存进度则是 `role="progressbar"` + 实时更新的 `aria-valuenow`，随时可查、不刷屏。

### 9. 自助排障：导出诊断包

设置页 →「数据与统计」→ **导出诊断包**。撞到「面板拒绝」「还原失败」「体积探测不出来」
这类问题时，截图 + 口述很难定位；这份 JSON 里装的是排障真正需要的那些东西：

- 版本号、平台 / 语言
- 当前全部设置（**站点排除列表只留条数**）
- 最近 20 条下载记录：时间、站点、文件名、状态、体积、失败原因
- 最近一次扫描的统计：来源分布、找到 / 截断、还原成功与未还原数、背景图与深度嗅探的截断情况、是否命中缓存
- 体积探测的累计成功 / 失败次数

**边界（这是重点）**：只含聚合数字与**主机名**，不含图片地址、页面地址、文件路径与查询串。
实现上不靠「我们记得别写进去」，而是三层：

1. **白名单**：字段逐个列出、逐个拷贝，绝不用 `Object.assign({}, entry)` 整体透传 ——
   以后给下载任务加一个 `referer`，黑名单会静默把它写进用户要公开粘贴的文件里，白名单只会少一个字段。
2. **`scrub()`**：任何写进去的字符串都把 `scheme://…` 替换成 `[url]`，于是
   「诊断包里不可能出现完整地址」是一条**结构上成立**的不变量。
3. **`audit()`**：落盘前把结果整体走一遍，发现漏网就**中止导出**并报出路径，而不是先写出去。

## 安装方法

### Chrome / Edge（开发者模式加载）

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 打开右上角的 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本目录 `image-hunter/`
5. 安装完成，工具栏会出现扩展图标（若未显示，点击拼图图标把「图片猎人」固定到工具栏）

> 修改代码后，回到扩展管理页点击该扩展卡片上的 **刷新** 按钮即可生效。

### 打包成 zip

```bash
node tools/package.js          # → dist/image-hunter-v<版本>.zip
node tools/package.js --list   # 只列出会打进包的文件
```

零依赖（压缩用 Node 内置的 zlib），也不需要先构建 —— 这个扩展本身就是零构建的。

打包前的白名单是**从 `manifest.json` 算出来的**，不是手写的清单：顺着 manifest
引用的资源递归展开（HTML 里的 `script` / `link` / `img` 也算引用），最后再反向检查
「运行时目录里有没有谁没被引用到」，有就报错并退出。手写清单迟早会烂 ——
加了个文件忘了写进去，打出来的就是残包，而且要**到用户装上才发现**。

时间戳固定，所以同样的源码永远打出字节相同的 zip（可复现构建）。

### 权限说明

| 权限 | 用途 |
|---|---|
| `downloads` | 保存图片到浏览器默认下载目录 |
| `storage` | 保存设置、下载历史、去重指纹 |
| `contextMenus` | 图片 / 页面右键菜单 |
| `scripting` | 在已打开的页面补注入内容脚本 |

（`alarms` / `notifications` / `activeTab` 在 v1.5.0 已删除 —— 声明了但从未使用。）

另外声明了 `host_permissions: ["<all_urls>"]`，这是「嗅探任意网页」这一核心能力的必然要求：
内容脚本要在你访问的任何页面上跑，才能找出图片并还原原图。
扩展**不上传任何数据**，所有设置 / 历史 / 指纹都只存在本机。
| `<all_urls>` | 嗅探任意网站的图片（含 iframe） |

扩展**不收集、不上传任何数据**，所有信息仅保存在浏览器本地。

## 使用说明

### 单张保存

1. 鼠标移到网页里的任意图片上
2. 右上角出现蓝色圆形下载图标
3. 单击 → 图标转圈 → 变绿色对勾，图片已保存到下载目录

> 想更快？按住 `Alt` 直接点击图片即可。

### 批量保存

1. 点击工具栏的扩展图标 → 图库在新标签页中打开
2. 顶部「扫描目标」确认是要处理的那个页面（可随时切换）
3. 直接点筛选条上的条件（尺寸 / 比例 / 格式 / 来源 / 其他），例如点 `≥ 1920px`
   - 筛选条**默认就是展开的**，不用先点按钮把它叫出来
   - 点「筛选」可以把它收起来腾空间，按钮上的数字角标会显示当前生效了几个条件
   - 搜关键词：点左上角 `🔍` 展开输入框，回车收起；有搜索词时图标会常亮
   - **尺寸那一格**：上排档位点一下就生效；下排滑条可以拖一个精确阈值（0–4096），
     默认 256 就已经在过滤小图了。**拖滑条会把上排档位复位成「全部」**（二者互斥）
   - ⚠️ **换筛选条件会取消掉「不在新结果里」的勾选**（会弹提示），
     所以「已选」永远等于你眼前能看到并勾上的数量，保存时不会多出看不见的图
4. 挑图（打开后默认一张都没选）：
   - **拖拽框选**（最快）：在网格里按住鼠标左键拖出一个矩形，松手即生效
     - 框内**没选过**的图片 → 勾上；框内**已经选过**的 → 取消
     - 所以连着框几次不同区域就是**不断累加**；框回刚才那片就是**把它们取消掉**
     - 按住 `Ctrl` 拖 = 只加不减（框到已选的也不会取消）
     - 按住 `Alt` 拖 = 只减不加
     - 拖拽中按 `Esc` = 放弃这次框选
     - 拖到网格上下边缘会自动滚动，长列表也能一次框完
   - 点卡片 = 勾选 / 取消；`Shift + 点击` 连选；`Ctrl/Cmd + A` 全选
   - 或直接点工具行里的 **全选**（按钮上写着当前筛选出多少张）
5. 点击右下角 **保存选中 (N)**
6. 底部出现实时进度条，完成后可查看成功 / 失败统计

> 想边看原页面边挑图？点图库右上角「在页面中打开图库面板」，
> 面板会从页面右侧滑出，和网页并排显示。

### 看体积 / 按体积排序

1. 点顶栏的 **仪表图标**（探测体积）—— 只对每张图发 `HEAD` 请求读响应头，**不会下载图片本体**；探测期间图标会转圈
2. 每张卡片右侧从格式名（如 `JPG`）变成真实文件大小（如 `1.18 KB`）
3. 「排序」选 **体积 大→小**，同分辨率下体积更大的通常画质更好
4. 勾选若干张后，底栏「合计」显示这次要下载的总量

> 拿不到体积的会显示 `—`（少数站点禁止跨域读取响应头）。再点一次「探测体积」会重试这些失败的。

### 打开页内面板

- 按 `Alt + Shift + S` 直接开关；或点图库右上角的「在页面中打开图库面板」
- 面板从目标页面右侧滑出，适合边浏览边勾选
- 按 `Esc` 或点右上角 ✕ 关闭

### 配置还原规则

1. 右键扩展图标 → **选项**（或扩展管理页 → 详情 → 扩展程序选项）
2. 找到「原图还原规则」
3. 在「规则调试」里粘贴一个缩略图地址，点「测试」
4. 会列出所有候选原图地址、各自的实际分辨率，以及是否会被采用
5. 如果某个站点的规则不适用，在「自定义规则」里添加正则即可

### 按站点 / 日期分目录保存

设置页 →「下载」→「保存到子目录」，填一个模板：

| 模板 | 结果 |
|---|---|
| （留空） | `下载目录/照片.jpg`（默认，与以前一致） |
| `{host}` | `下载目录/example.com/照片.jpg` |
| `{date}/{host}` | `下载目录/20260929/example.com/照片.jpg` |
| `shots/{index}` | `下载目录/shots/007/照片.jpg` |

- 变量与文件名模板共用一套：`{host}` 站点 · `{date}` 日期 · `{index}` 序号
- 路径会做安全清洗：`..` 被丢掉、开头的 `/` 去掉、非法字符换成 `_`、最多 3 层
- 悬停保存成功时的气泡会告诉你存到了哪一层（`已保存 600×400 → example.com/`）
- 下载历史里记的是含子目录的相对路径，方便照着去找文件

> 顺带一提：文件名模板里直接写 `/` 也当子目录用（`{host}/{name}.{ext}`），
> 这个能力一直都有，只是以前没写进文档。

### 排除某些站点

设置页 →「站点排除列表」，一行一个域名：

- 一条记录会匹配**它自己 + 它的所有子域名** —— 写 `example.com` 就覆盖了 `www.example.com`
- 直接粘贴完整网址（`https://example.com/photo`）会自动取出域名，大小写和多余的点也会归一
- 输入框下方会实时告诉你「会排除 N 个站点」以及哪些行不合法（不合法的行会被忽略）

被排除的站点上：**不显示悬停按钮、不响应 Alt+点击、不开页内面板，也不会自动嗅探**；
点扩展图标打开图库时会明确告诉你「这个站点在你的排除列表里」，而不是给一个空列表。

两点需要说清楚：

- **扩展的文件仍然会被加载**。Manifest V3 的 `content_scripts` 是静态声明，没有「按站点跳过加载」的办法 ——
  这里关掉的是**界面行为**，不是注入本身。
- **右键菜单里的「保存这张图片」仍然可用**。那是你自己点出来的动作，不算打扰。
- **从灯箱点「在图库中打开」也不受影响**。同上 —— 那是你主动点的。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Alt + Shift + S` | 打开 / 关闭页内图库面板 |
| `Alt + Shift + G` | 在新标签页打开图库（和点扩展图标完全一样，会复用已开的图库页） |
| `Alt + Shift + D` | 保存**鼠标当前悬停的那张图** |

`Alt + Shift + D` 有个细节：如果**灯箱正开着**，它保存的是**你正在看的那一张**，
而不是鼠标底下那张 —— 灯箱是全屏的，这时候鼠标多半根本没停在图片上。
两个条件都不满足时，页面底部会弹一句「先把鼠标移到图片上」，不会按了毫无反应。

快捷键都可以在 `chrome://extensions/shortcuts`（Edge 是 `edge://extensions/shortcuts`）里改。

### 重新打开图库不用等

同一标签页、同一个地址，5 分钟内再次打开图库会**直接复用上次的嗅探结果** ——
省掉「重新注入内容脚本 + 重新给每张候选发加载请求做原图还原」的那几秒。

- 底栏会如实标出「**（复用 N 分钟前的嗅探结果 · 点此重新嗅探）**」，
  不会让你误以为是刚扫的。点这句话本身就是重新嗅探
- 顶栏的「重新嗅探」按钮和「深度嗅探」**一律绕过缓存**，点了就是真扫
- 这些情况缓存自动作废：页面**刷新**（URL 没变但内容重来了）、**导航**到别的地址、
  标签页被关闭、**设置被改动**（扫描来源 / 还原规则都可能变了）
- 站点在排除列表里时不会留下缓存，每次都按最新设置重新判断

### 版本控制约定

仓库里只放**人写的**东西。凡是用脚本能重新生成的都不进仓库 ——
依赖（`node_modules/`）和打包产物（`dist/`）都在 `.gitignore` 里。

唯一的例外是 `docs/screenshots/`：它同样是脚本生成的，但作为界面演进的记录值得留一份历史，
所以明确纳入。`tests/screenshot.js` 的默认输出目录就是它（第二个参数可以改）。

行尾一律 LF（`.gitattributes` 里 `* text=auto eol=lf`）。这条不是洁癖：
测试里没有任何 `\r` 归一化，`validate.js` 直接按原始字节对 `popup.html` 做正则匹配，
混用行尾会让「跨行断言」在 CRLF 文件上**静默失配** —— 表现为「断言压根没命中」，
比直接报错难查得多。

## 技术要点

- **零构建、零依赖**：原生 ES2020，不需要 npm / webpack，直接加载即可运行
- **Shadow DOM 隔离**：所有页内 UI 都封装在 Shadow DOM 中，站点 CSS 无法污染它，它也不会污染站点
- **多 iframe 汇总**：内容脚本注入到所有 frame，各 frame 独立扫描后回传结果由后台合并去重
- **MV3 休眠应对**：下载任务托管给浏览器 `downloads` API；队列持久化到 `storage.session`，Service Worker 被回收后可自动恢复未完成的下载
- **并发限流**：尺寸探测与下载都有并发控制，图片再多也不会拖垮页面

## 常见问题

**Q：界面有英文版吗？**
A：**没有，界面文案目前 100% 是中文硬编码。** 仓库里的 `_locales/` 只有 6 个键
（扩展名称、描述、命令标题），它们是给 manifest 用的，不覆盖任何界面文字。
之所以现在做成这样：这个扩展的界面有 300 多条文案，抽取 + 翻译 + 校对是一笔
不小的投入，而目前没有明确的需求。想要英文界面的话欢迎提 issue。

**Q：某些图片保存失败？**
A：少数站点有严格的防盗链校验。扩展会自动尝试降级方案（改用扩展页拉取），若仍失败，可在图片上右键选择「在新标签页打开原图」后手动保存。

**Q：为什么某张图没显示下载图标？**
A：默认小于 64px 的图片不显示图标（避免小图标、分隔条干扰）。可在设置页调低「最小显示尺寸」。

**Q：图库里能看到某张图，但大图预览里翻不到？**
A：「大图预览最小尺寸」（默认 64px）在起作用 —— 它只作用于灯箱，图库列表不受影响，
所以会出现两边数量不一致。灯箱底部会写明「已按 64px 过滤 N 张」。想让它也出现在预览里，
把这一项调成 0（不过滤）。

**Q：图库打开后有些小图不显示，是不是嗅探漏了？**
A：不是。筛选条「尺寸」那一格的下排滑条**默认就是 256**，短边小于 256px 的图会被过滤掉。
滑条右侧和「筛选」按钮上的角标都会实时显示条件数。想看全部，把滑条拖到 **0**。

**Q：尺寸那一格的上排档位和下排滑条，哪个说了算？**
A：**档位优先，二者互斥。** 上排选了非「全部」就听档位（判**宽度**，如 `≥ 800px` = 宽 ≥ 800）；
上排是「全部」时才听滑条（判**较短边** ≥ 阈值）。档位生效时滑条会变淡并显示提示；
**拖动滑条会自动把档位复位成「全部」** —— 因为拖动就是「我要用连续这一把」的意思。

**Q：滑条设的值重开图库就没了 / 会不会被导出？**
A：值会保留，但它是**视图状态**（存在本地 `chrome.storage.local`），
和排序、搜索词同类 —— **不写进设置页，也不进导出/导入的 JSON**。
换台机器或重装扩展，它会回到默认 256。

**Q：这两个尺寸设置有什么区别？**
A：**「最小显示尺寸」管悬停图标**，判的是页面上的**显示大小**，决定要不要出现下载按钮。
**「大图预览最小尺寸」管灯箱翻页**，判的是图片的**真实像素尺寸**，决定能翻到哪几张。
一个管「能不能点」，一个管「翻不翻得到」，互不影响。

**Q：还原后的原图打不开？**
A：还原候选都会先实测加载，只有确认能加载且更大才会采用，正常情况下不会出现这种情况。如果遇到，请在设置页的「规则调试」里验证并调整规则。

**Q：如何让之前下载过的图片重新允许下载？**
A：设置页 → 数据与统计 → 清除去重指纹。

**Q：点了悬停下载图标，提示「已保存」，但下载目录里没有？**
A：先看提示的具体文案：
- 显示 **「已下载过，本次已跳过」** —— 这张图之前存过，指纹命中了。
  去「设置页 → 数据与统计 → 清除去重指纹」即可重新下载。
- 显示 **「（实际为 xxx.avif）」** —— 浏览器按真实格式纠正了扩展名，
  请按提示的文件名去找，而不是原来的 `.jpg`。
- 确实显示「已保存」但仍找不到 —— 检查浏览器下载设置里的默认下载目录，
  以及是否开着「下载前询问保存位置」。设置页可以调整下载子目录与文件名模板。

**Q：下载下来的图片格式和扩展名对不上？**
A：这是 CDN 转码导致的。扩展会尝试去掉 `?x-bce-process=` / `?x-oss-process=` 等
图片处理参数，拿回未经转码的原图。若某站点仍如此，可在设置页的「规则调试」里
加一条自定义规则去掉对应参数。

**Q：点了「探测体积」提示失败 / 一直显示 —？**
A：先确认已经**重新加载过扩展**（`chrome://extensions` 上点该扩展的刷新按钮）。
早期版本这里有一个 bug：消息常量名写成了复数 `PROBE_SIZES`（实际定义是 `PROBE_SIZE`），
导致请求发出去后台直接忽略、永远弹「体积探测失败」——已在 v1.2.1 修复。
如果重新加载后仍有部分图片显示 `—`，那是站点层面禁止跨域读取响应头（没有 `Content-Length`
且不支持 `Range`），属于正常情况，不影响下载。

**Q：探测体积会消耗流量吗？**
A：几乎不会。它只发 `HEAD` 请求读响应头；只有站点不支持 HEAD 时才会降级成
`Range: bytes=0-0`，也只取 1 个字节。

**Q：一页几百张图，点一次「探测体积」能全部探到吗？**
A：能。探测是**按 120 张一批循环发**的，点一次会一直推进到所有待探测的图都试过一轮。
早期版本只发一批（120 张）就收工，而失败项又被算作「待探测」——
于是前 120 张只要全部失败（站点禁止跨域），再点多少次都还是那同一批，第 121 张之后永远轮不到。
现在失败项单独记账，全部探过一轮后再点一次才进入「重试失败项」。

**Q：点了「停止」之后，下载目录里还是多出来几个文件？**
A：这是正常的。`chrome.downloads` 一旦开始落盘就没有安全的撤回手段（强行取消会留下半个文件），
所以「停止」只能清掉**还没开始**的队列，已经在飞的几张会照常下完。
提示会如实写明「已取消队列中 N 张；正在下载的 M 张会继续完成」，进度条上也会标出这几张。

**Q：我勾了几张，一换筛选条件勾选就没了？**
A：这是**刻意设计**的。筛选在这里的语义是「缩小工作集」——不在新结果里的图片会被自动取消勾选，
并弹一句「已取消 N 张不在当前筛选内的勾选」。这样「已选 N」永远等于你眼前能看到并勾上的数量，
点「保存选中」不会多出几张已经被筛掉、看不见的图。
代价是没法「框一批 → 换条件 → 再框一批 → 一起保存」。需要这种累加的话，
先别筛，直接拖拽框选把一批攒起来，最后再筛一遍确认。

**Q：为什么「全选」和以前的「选中筛选结果」变成一个按钮了？**
A：因为勾选已经限定在筛选结果内，两者本来就是同一件事。合并后「全选」按钮上直接标着
当前筛选出多少张，一眼就知道会勾上几张。

**Q：页面图片特别多的时候，底栏那句「仅展示前 2000 张」是什么意思？**
A：单次嗅探最多返回 2000 张（再多界面也看不过来，消息序列化也会拖慢）。
超过时会如实标出真实总数，例如「（本页共 2317 张，仅展示前 2000 张）」。
另外如果页面元素超过 8000 个，CSS 背景图扫描会只覆盖前 8000 个元素，
这时也会有一句提示——`<img>` / `srcset` / `preload` 等来源不受影响。

**Q：在某个网站里看到了「这个页面不是由图片猎人打开的，已拒绝在此显示图库」？**
A：这是**安全防护**，不是故障。页内面板本质是「网页里的 iframe 加载扩展页」，
任何网站都能构造同款 iframe，把图库叠在自己页面上诱导你点击（套壳点击），
或者靠「能不能加载这个资源」探测你有没有装这个扩展。
所以内容脚本打开面板时会先向后台领一个只属于本标签页的随机 token 写进 iframe 地址，
面板启动时拿它回后台核验——网站拿不到 token，伪造的 iframe 一律拒绝启动。
正常从扩展图标 / 快捷键 `Alt+Shift+S` 打开的面板不受影响。
（独立标签页 `?mode=page` 不需要校验：那是扩展自己开的页面，网页碰不到。）

**Q：底栏写着「复用 N 分钟前的嗅探结果」，是新扫的吗？**
A：**不是**，那是如实告诉你「这是缓存」。同一标签页、同一个地址，5 分钟内重开图库
会直接复用上次的结果，省掉重新注入 + 重新还原原图的几秒。点那句话（或顶栏的
「重新嗅探」）就会真的重扫，标记随即消失。
页面刷新、导航到别的地址、关掉标签页、改动设置，缓存都会自动作废。

**Q：悬停预览要等一两秒才打开？**
A：是的，这是**刻意**的取舍。点放大镜后会先把本页扫一遍拿到还原后的原图列表，
期间按钮转圈 + 气泡显示「正在整理本页图片…」。这样打开就能直接左右翻看原图；
如果先把页面上的缩略图地址铺出来，翻到一半图会自己变成另一批 URL，更难受。
同一页面第二次点预览会命中扫描缓存，基本是瞬时的。

**Q：悬停预览翻的范围是什么？**
A：当前这一页的全部图片，按**页面顺序**，与图库同源（含 CSS 背景图、链接指向的图等，
按设置页的扫描来源开关走）。翻到末尾再往后绕回第一张。
如果那一页一张图都没扫到（例如整页都是 canvas 绘制的），灯箱就只显示你点的那张，
计数是 `1 / 1` —— 不会假装还有别的。

**Q：快捷键 `Alt+Shift+D` 按了没反应？**
A：先确认鼠标确实停在图片上（要等悬停按钮浮现出来）。如果灯箱正开着，它保存的是
灯箱里那张。两个都不满足时，页面底部会弹一句「先把鼠标移到图片上」。
另外快捷键可能和别的扩展冲突，可在 `chrome://extensions/shortcuts` 查看与修改。

v1.13.1 —— 修一个用户报的 bug：**「首次点击扩展图标，嗅探有问题，要刷新下才行」**。
          它看起来像嗅探坏了，其实是**扫描的结论只有两态**惹的祸。

          **现象与根因**：`background.js` 的 `scanTab()` 一开始就挂一个 4 秒兜底计时
          （`SCAN_IDLE_TIMEOUT`），本意是「内容脚本完全没接上话就放弃」。可它同时也在给
          内容脚本的**正常加工**计时 —— 而加工的第一步是「补尺寸」，只能靠真实加载：
          页面自己还没加载的图（懒加载、首屏之外）就得等网络，每张最多 `probeTimeout`，
          并发只有 6。真实站点上十几张没加载的图，就足够把首次回报推迟到 4 秒以上。

          4 秒一到就收尾，此刻**一个 frame 都还没回报** → 结果是 `ok: true` + 空列表 →
          图库照直说「本页没有发现图片」。用户看着满屏的图，被告知这页没有图。
          **刷新一下为什么就好了**：第二次的探测结果已经在内容脚本的缓存里，
          回报是毫秒级的 —— 这也正是这个 bug 一直没被测试抓到的原因：
          所有浏览器用例都在页面加载完之后才扫描，那时尺寸早就知道了。

          **修法（四处，缺一不可）**：

          | 位置 | 改动 | 为什么 |
          |---|---|---|
          | `content/scanner.js` | 「先出图」的中间结果从「补尺寸之后」挪到**之前** | 首次回报的耗时改由**采集**（纯 DOM，快且可控）决定，不再由联网步骤决定。尺寸未知的候选照常出现（图库对「尺寸未知」本来就刻意放行），补完尺寸的最终结果随后原地替换 |
          | `background.js` `scanTab()` | 收到内容脚本对 `DO_SCAN` 的**确认**之后，把兜底计时从「没接上话」档放宽到加工档 | 内容脚本已经接话了，就说明它在跑、只是还没跑完。「没动静」这个判据从此只覆盖「注入 + 投递」那一段 |
          | `background.js` `finalizeScan()` | **一个 frame 都没回报 → 判失败**，不是「成功但 0 张」 | 立一条不变量：「没问成」永远不等于「没有图」。同理，frame 自报的 `busy` / 异常也不再被丢掉 |

v1.12.0 —— 多标签页合并嗅探：一次把好几个已打开页面的图片合并成一份列表（**可选开关，默认关**）。

          「这一页有哪些图」是绝大多数时候想知道的，「这几页加起来有哪些图」是偶尔才要的。
          所以它做成一枚**设置开关**（`mergeTabs`，默认 `false`），而不是默认替用户打开 ——
          打开后，图库顶部的「扫描目标」从**单选下拉**变成**多选勾选列表**，
          勾几个就把这几页的图片并成一份。

          开关改完**当场生效**（不用刷新图库、也不用重启浏览器）：`popup.js` 挂在
          `Store.onChange` 上，`sel.hidden = mergeTabs` / `multi.hidden = !mergeTabs`
          两个控件互斥显示，从多选切回单选时把勾选收缩成「当前这一个」。

          **去重按「图片地址」**（`U.normalizeUrl` 规范化之后）。同一张图出现在两个页面上
          （比如列表页和详情页都挂了它）只留一份，卡片上标出它来自哪几个页面。

          | 细节 | 做法 | 为什么 |
          |---|---|---|
          | 每页传 `finalOnly: true` | 合并路径**不要**中间结果 | 「先出图、后升级」的 `partial → SCAN_UPGRADE` 是**按 tabId 配对**的。多页并发时，A 页的升级广播会把 B 页刚铺好的结果盖掉 |
          | 结果合并 | `mergeTabResults(ids, results)`，纯函数 | 每张图带 `pageIndex / pageUrl / pageHost / pageHosts[]`，`order` 重排成全局序号。单页路径完全不走这里 |
          | 装结果 | 单页与合并**共用** `adoptScanResult()` | 免得「把结果写进 state 再渲染」这件事有两份实现、日后分叉 |
          | 连点复选框 | `U.debounce(…, 260)` | 否则每勾一下都并发跑一轮 N 页扫描，各自 `await` 完后都写 `state.all`，列表会闪 |
          | 「站点」排序 | 先按**来源页**分组，页内再按图片域名 | 合并时「站点」的直觉是「先看这一页的，再看那一页的」。单页时 `pageIndex` 恒为 0，自动退化成纯域名排序 |
          | 搜索 | 连 `pageUrl` 一起匹配 | 想只看某一页的图，敲那页的地址片段就该筛出来 |
          | 导出 | CSV / JSON 多一列「来源页」 | 合并结果的 `filename` 前缀是 `merged_<N>pages` |
          | 空态 | 区分「还没勾选」与「勾了但这些页面没有图」 | 前者是用户还没做选择，后者是确实没有 —— 混成一句会让人以为功能坏了 |
          | 页内面板 | **恒为单目标** | 面板是「看这一页」，给它多选没有意义 |

          **顺手修掉一个真缺陷**：`background.js` 的 `finalizeScan()` 从来没有写过
          `img.host`。而图库的「站点」排序和 CSV 导出的「站点」列一直在读 `c.host` ——
          于是那条排序实际上是在比较**空串**，永远退化成按面积排。现在补上
          `img.host = U.prettyHost(img.url)`，那个选项才名副其实。

          > 注意别和「来源页」搞混：`pageUrl` 记的是「这张图出现在哪个页面」，
          > 而 `host` 是图片文件自己所在的域名（常常是 CDN，和页面不同域）。

          测试：`tests/browser-merge-tabs.js`（新，39 项 / 10 节，两个本地站 ——
          一个是**同站两页且故意让第 3/4/5 张两页都有**、另一个**换 host** 造跨站无重叠的对照）；
          `validate.js` 第 14 节（新，11 条静态守卫，专门钉「默认必须是关的」与「设置页必须有开关」）。
          注入验证 5 项：「默认值改 true」→ validate 红 1、「去掉合并路径的 `finalOnly`」→ 红 1、
          「关掉跨页去重」→ browser 红 3、「去掉来源页角标」→ browser 红 1、
          「`loadTabList` 用勾选反向覆盖 `tabId`」→ browser 第 10 节红 2。

          > **写这个功能时真的撞了一个回归**：重写 `loadTabList()`（它同时填单选下拉与
          > 多选勾选列表）时，末尾加了一句「保持 `tabId` 与勾选同步」——在**合并模式**下
          > 这是对的，但在**单选模式**下它会把 `switchTarget()` 刚设好的新目标覆盖回旧的，
          > 于是「图库开着时再点一次图标切到另一页」当场被撤销（下拉和顶栏都换了、图还是旧的）。

          免得用户以为嗅探漏图。

          三个设计决定是问过用户才定的：

          | 问题 | 决定 | 为什么 |
          |---|---|---|
          | 作用范围 | **只管灯箱** | 图库卡片、批量下载、悬停图标全不受影响。落点在 `lightbox.open()`，**不是** `scanner.isValidCandidate()` —— 后者被图库和批量下载共用，放那儿就违反「只影响预览」 |
          | 判据 | **较短边**（宽高都要达标） | 分隔条那种 `1200×8` 最长边 1200 远超门槛，只看最长边它反而合格 —— 而那正是最该滤掉的一类 |
          | 默认值 | **64，开箱即过滤** | 与「最小显示尺寸」对齐，开箱就干净 |

          **为什么不复用手上已有的 `minSize`** —— 它们是两件事：

          ```
          minSize           判「页面显示尺寸」（getBoundingClientRect）
                            决定悬停下载图标显不显示         → hover.js:338
          lightboxMinSize   判「图片真实像素尺寸」（探测得到的 width/height）
                            决定灯箱里能翻到哪几张           → lightbox.js
          ```

          `minSize` 用它自己的尺子，一个字节都没动。

          三条边界值得单独记：

          1. **过滤后定位不能偏。** `startIndex` 是**原列表**下标，过滤会把前面的项挤走。
             所以先按当前这张的**地址**在原列表里认位置，再从过滤后的列表里按同一张图
             重新定位 —— 否则「点第 6 张、打开是第 2 张」。
          2. **尺寸未知的一律放行。** 探测超时的候选 `width/height` 还是 0，
             拿 `w < min` 判死会静默藏图。判断权交给用户，不交给超时。
          3. **一张都不剩时必须还能打开。** 阈值高到把候选全筛掉时（真实的「点了一张小图标」），
             放开过滤只显示用户点的那一张 —— 「点了预览什么都没弹」是最糟的结果。

v1.5.1 —— 修复「首次点开图库偶尔一张图都识别不到」。

          根因不在采集，而在**收尾判据**：原图还原要给每张图的每个候选发一次真实
          加载请求，那类页面上 65 张全是 CDN 缩略图代理地址，冷加载时这一轮轻松
          超过 1 秒；而后台的判据是「1.5 秒内有 frame 响应就算数，否则收尾」——
          它分不清「没有响应」和「正在还原」，于是把正常的慢扫描判定成「本页没有图片」。
          第二次打开时图片已进 HTTP 缓存、还原秒完，所以表现为「偶尔」。

          三处修改：
          - 后台删掉「1.5 秒无响应即收尾」，只在内容脚本**完全没动静**时才兜底（4 秒）；
            收到中间结果后把兜底放宽到还原阶段的量级（15 秒）
          - 内容脚本分两阶段回报：先交出「已采集、未还原」的中间结果，
            还原跑完再交最终结果覆盖它。中间结果既是「扫描确实在进行」的证据，
            也是还原超时的保底 —— 用户不会看到空列表
          - 还原阶段加全局并发闸门（8）与时间预算（8 秒）。原先是
            `Promise.all(list.map(...))` 无节制地打请求，65 张 × 6 条规则会一次
            打出几百个加载；撞上预算时如实标记，底栏提示「原图还原超时，
            靠后的部分图片仍是页面上的版本」
